# Load tests (k6, open model)
- Seed first: `make seed` (runs `seed.sql`: 100k links `lt00000`..`lt99999`). Run: `make load SCENARIO=ramp`, or from the host `k6 run ramp.js` (default BASE_URL http://localhost:8080). Knobs via `-e NAME=value` (see the header comment of each script and `lib/config.js`).
- `smoke.js`: correctness gate covering every endpoint. `ramp.js`: 90/5/5 mix (redirects, creates, API reads), Zipf-skewed redirects, 30 s warm-up then +200 rps every 30 s up to 3000 rps. It finds the knee and stops once latency or errors collapse. `cache-miss.js`: the same ramp with uniform codes, to show what the cache is worth. `spike.js`: baseline, a 10× redirect spike, then recovery. `ratelimit.js`: anonymous 201s then 429s, keyed traffic unaffected.
- SLO: redirect p99 < 50 ms, errors < 0.1 %. Thresholds fail past the knee on purpose (k6 exits 99). The per-phase table in the summary gives the max sustained rps. The full JSON is saved in `results/<testid>.json`.
- In Grafana, k6 series carry labels `testid`, `scenario`, `endpoint`, `phase`, and `name` (e.g. `k6_http_req_duration_p99{endpoint="redirect"}`). Read them together with the API panels for the same time range.
